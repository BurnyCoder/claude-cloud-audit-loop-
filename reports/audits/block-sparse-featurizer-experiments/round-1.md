# Fact-check audit: BurnyCoder/block-sparse-featurizer-experiments, round 1
## Summary

The repository has no committed result files, paper, or Pages UI. Its claim surfaces are README.md, AGENTS.md, code docstrings and comments, the launcher notebook, and the four Hugging Face model cards generated by `hub_release._model_card`. I checked them against the following evidence:
- the arXiv paper 2606.25234 (abstract page, HTML full text, HF paper metadata);
- the pinned submodule `vendor/block-sparse-featurizer` at 0569021, plus the upstream LICENSE fetched raw at commit 0bf2d9a;
- `uv.lock`, `pyproject.toml`, the source modules and the CI workflow;
- the HF API (repo SHAs, LFS SHA-256s, gating) and the hosted `manifest.json` and `README.md` of all four checkpoints;
- official Gradio and huggingface_hub docs.

The code checks out. All four `CHECKPOINT_CATALOG` revisions, SHA-256s and sizes match the Hub exactly. The presets match the upstream README and notebooks, and the `.env` defaults match `config.py`. Lockfile versions, the 300x224x224x3 rabbit dataset and the (196, 768) positional mean all match. Every non-GitHub URL in the repo resolves. All README errors were in prose:
- an LLM overclaim;
- imprecise submodule provenance;
- an unsourced Scores table that mixes two different R² measurements.

All fixes are README-only (3 commits).
